# Contribuindo com o Tilo

> Pull Requests são analisados conforme a disponibilidade do mantenedor.

## Antes de tudo

Leia o [`CLAUDE.md`](CLAUDE.md) e a documentação em [`docs/`](docs/) (fonte de verdade). Rode `npm test` antes de enviar.

## Issues

Bugs e sugestões são bem-vindos por Issue. **Não inclua segredos, tokens, caminhos pessoais nem dados de clientes.** Falhas de segurança seguem o [`SECURITY.md`](SECURITY.md), não Issue pública.

## Pull Requests e DCO

Enviar um PR não dá direito automático de alterar o repositório oficial: o mantenedor revisa segurança, testes, documentação e direitos sobre o código.

Todo commit precisa de `Signed-off-by` (use `git commit -s`). Com isso você declara o [Developer Certificate of Origin 1.1](https://developercertificate.org/): que escreveu o código ou tem direito de enviá-lo.

Além disso, ao enviar uma contribuição você concorda que:

1. ela é enviada sob a licença do projeto (PolyForm Noncommercial 1.0.0); e
2. o titular do projeto (Fabio Bragato) pode usá-la, modificá-la e sublicenciá-la também nas licenças comerciais do Tilo (Business/Enterprise) e em futuras versões da licença do projeto.

Se não concordar com o item 2, não envie código; sugestões por Issue continuam bem-vindas. O mantenedor pode recusar contribuições sem Signed-off-by ou sem origem clara.

## Marca

O código não dá direito de usar o nome "Tilo" nem a identidade visual para outros produtos.
